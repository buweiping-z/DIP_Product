🔍 发现的问题与建议
一、数据模型问题
1. InventoryLot 缺少 PartId 冗余字段（P0）
sql
-- 当前设计
InventoryLot:
  - InventoryId (FK)
  - LocationId (FK)

-- 问题：查询批次时需 JOIN Inventory 才能获取 PartId
-- 建议：冗余 PartId
InventoryLot:
  - InventoryId (FK)
  - PartId (FK)  -- 🆕 冗余
  - LocationId (FK)
理由：

FIFO查询需要按 (PartId, LocationId, Status) 过滤

批次追溯需要直接查 PartId

避免频繁 JOIN Inventory 表

2. PrepDetail 缺少 ActualQty 累计校验约束（P1）
当前设计允许 ActualQty 无限累加，应增加业务层校验：

csharp
// 备料时校验
if (detail.ActualQty + quantity > detail.RequiredQty)
{
    throw new BusinessException($"备料数量超过需求，需求:{detail.RequiredQty}");
}
建议： 在数据库层添加 CHECK 约束（MySQL 8.0 支持）：

sql
ALTER TABLE PrepDetail ADD CONSTRAINT CHK_ActualQty_LE_RequiredQty 
    CHECK (ActualQty <= RequiredQty);
3. OnlineConfirm 缺少 LocationId 字段（P1）
当前只有 SourceLocationCode（冗余），缺少外键 SourceLocationId：

sql
OnlineConfirm:
  - SourceLocationId BIGINT FK→WarehouseLocation.Id  -- 🆕 新增
  - SourceLocationCode VARCHAR(30)  -- 保留冗余
理由： 冗余字段仅用于显示，外键用于关联查询和保证数据一致性。

4. PartSubstitute 缺少 SubstituteReason 字段（P2）
sql
ALTER TABLE PartSubstitute ADD COLUMN SubstituteReason VARCHAR(200) COMMENT '替代原因';

6. 备料单生成未考虑「替代料自动匹配」（P1）
当前设计：BOM 中已指定 SubstitutePartId

建议增强： 如果正料库存不足，系统自动推荐可用替代料：

csharp
// PrepOrderService.GenerateFromBOM()
foreach (var bomItem in bomItems)
{
    var primaryPart = bomItem.Part;
    var availableQty = await GetAvailableQty(primaryPart.Id);
    
    if (availableQty < bomItem.RequiredQty)
    {
        // 查询替代料
        var substitutes = await _substituteRepo
            .FindAsync(s => s.OriginalPartId == primaryPart.Id && s.Status == 1)
            .ToListAsync();
            
        foreach (var sub in substitutes)
        {
            var subQty = await GetAvailableQty(sub.SubstitutePartId);
            if (subQty >= bomItem.RequiredQty)
            {
                // 推荐替代料，标记 SubstituteFlag=1
                break;
            }
        }
    }
}
7. FIFO 选取未考虑「多库位」场景（P1）
当前 FIFO 查询只针对单个 LocationId：

sql
-- 当前
SELECT * FROM InventoryLot 
WHERE PartId = @partId AND LocationId = @locationId AND Status = 1
ORDER BY ReceiptDate ASC LIMIT 1;
增强建议： 如果同一部品分布多个库位，应跨库位按 ReceiptDate 全局排序：

sql
SELECT * FROM InventoryLot 
WHERE PartId = @partId AND Status = 1 AND (ExpiryDate IS NULL OR ExpiryDate > NOW())
ORDER BY ReceiptDate ASC LIMIT 1;
8. 上线确认缺少「批次拆分量」校验（P1）
当前设计：一次上线确认数量 LoadedQty 可以等于批次数量或部分数量

建议增加： 如果 LoadedQty < 批次数量，系统自动拆分批次：

csharp
// 上线时
if (loadedQty < lot.Quantity)
{
    // 拆分批次：创建新批次 (剩余数量)
    var remainingLot = lot.Clone();
    remainingLot.Quantity = lot.Quantity - loadedQty;
    remainingLot.Status = 1; // 可用
    
    // 当前批次 Quantity = loadedQty
    lot.Quantity = loadedQty;
    
    // 当前批次出库
}

五、性能与可靠性问题
13. Inventory 汇总表更新「热点行」性能（P1）
高并发场景下，同一 (PartId, LocationId) 的 Inventory 行会成为热点（大量并发 UPDATE）。

优化方案：

批量合并更新： 将 10 笔备料操作合并为 1 次 Inventory 更新（使用内存队列聚合）

异步更新： 备料操作成功后，Inventory 更新放入消息队列异步执行

Redis 预热： 高频查询的库存数据预热到 Redis

14. 缺少「数据迁移脚本」版本管理（P2）
建议使用 EF Core Migration 管理数据库变更：

15. 操作日志缺少「敏感字段脱敏」配置（P1）
