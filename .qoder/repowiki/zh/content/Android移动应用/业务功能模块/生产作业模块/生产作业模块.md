## 引言
本文件面向DIP系统Android应用的生产作业模块，覆盖备料、补料与上架三大核心流程，并补充生产状态监控、异常处理、进度反馈、效率统计、质量追溯与合规性检查等能力说明。文档以“从前端到后端”的端到端视角组织，既便于一线作业人员理解操作路径，也便于开发者定位实现细节。

## 项目结构
生产作业模块由Android移动端与.NET Web API后端组成：
- Android端负责扫码采集、界面交互、本地状态管理与网络请求封装。
- 后端提供REST接口，承载业务逻辑、数据持久化与跨模块协作（库存、位置、物料需求、异常、报表等）。

## 核心组件
- 备料（Prep）：完成备料准备、物料核对、任务分配与执行确认。
- 补料（Refill）：触发条件判断、审批流转、库存扣减与记录。
- 上架（Shelving）：扫描确认、库位管理、批次跟踪与入库登记。
- 支撑能力：库存（Inventory）、库位（Locations）、异常（Abnormal）、报表（Report）。

## 架构总览
生产作业模块采用“前端页面 + ViewModel + 网络层”与“控制器 + 服务层 + 数据访问”的分层架构。Android端通过统一的ApiService调用后端REST接口；后端控制器仅做参数校验与路由转发，核心业务在Service层实现，并通过Entity Framework上下文访问数据库。

```mermaid
sequenceDiagram
participant U as "用户"
participant S as "Android 页面/ViewModel"
participant N as "ApiService/Retrofit"
participant C as "后端控制器"
participant SV as "Service 层"
participant DB as "数据库"
U->>S : 触发操作如提交备料/补料/上架
S->>N : 构造请求携带Token/扫码数据
N->>C : HTTP 请求
C->>SV : 调用业务方法
SV->>DB : 读写实体库存/库位/批次等
DB-->>SV : 返回结果
SV-->>C : 业务结果
C-->>N : JSON 响应
N-->>S : 解析响应
S-->>U : 展示结果/下一步引导
```

## 详细组件分析

### 备料作业（Prep）
- 准备工作
  - 选择工单/批次，加载所需物料清单。
  - 校验物料可用性（库存、替代策略、有效期）。
- 物料核对
  - 扫码比对条码与BOM/需求单，记录差异。
  - 支持批量核对与快速纠错。
- 任务分配
  - 将备料任务下发至指定工位/人员。
  - 支持分派、回退、重分配。
- 执行与确认
  - 完成后提交确认，更新备料状态与库存占用。
  - 生成备料记录用于追溯。

```mermaid
flowchart TD
Start(["进入备料"]) --> LoadPlan["加载计划与物料清单"]
LoadPlan --> CheckAvail["校验可用性与替代规则"]
CheckAvail --> |不足| CallMat["发起呼叫物料"]
CheckAvail --> |充足| ScanCheck["扫码核对物料"]
ScanCheck --> Diff{"是否差异?"}
Diff --> |是| RecordDiff["记录差异并提示"]
Diff --> |否| AssignTask["分配备料任务"]
RecordDiff --> AssignTask
AssignTask --> Execute["执行备料"]
Execute --> Confirm["提交确认"]
Confirm --> UpdateState["更新状态与占用"]
UpdateState --> End(["结束"])
```

### 补料流程（Refill）
- 触发条件
  - 线边库存低于阈值或按消耗自动触发。
  - 人工发起补料申请。
- 审批流程
  - 创建补料申请，走审批流（可配置多级审批）。
  - 审批通过后生成补料任务。
- 库存调整
  - 出库扣减、在途登记、到货确认。
  - 与备料/上线消耗联动，确保账实一致。

```mermaid
sequenceDiagram
participant U as "用户"
participant R as "补料界面/ViewModel"
participant API as "ApiService"
participant RC as "RefillController"
participant RS as "RefillService"
participant INV as "InventoryService"
participant DB as "数据库"
U->>R : 发起补料申请
R->>API : POST 补料申请
API->>RC : 路由到控制器
RC->>RS : 校验与创建申请
RS->>DB : 写入申请记录
DB-->>RS : 成功
RS-->>RC : 返回申请ID
RC-->>API : 返回结果
API-->>R : 展示审批状态
Note over R,RS : 审批通过后自动生成补料任务
R->>API : 提交出库/到货确认
API->>RC->>RS->>INV->>DB : 扣减库存并登记流水
```

### 上架操作（Shelving）
- 扫描确认
  - 扫描物料条码与库位码，进行绑定校验。
  - 支持批次、效期、序列号等多维信息录入。
- 位置管理
  - 库位容量、分区、优先级策略。
  - 推荐库位与冲突检测。
- 批次跟踪
  - 批次号、生产日期、到期日、供应商批号。
  - 正向/反向追溯查询。

```mermaid
flowchart TD
Start(["开始上架"]) --> ScanItem["扫描物料条码"]
ScanItem --> ValidateItem["校验物料与批次"]
ValidateItem --> ScanLoc["扫描库位码"]
ScanLoc --> ValidateLoc["校验库位可用性与容量"]
ValidateLoc --> Bind["绑定物料-库位-批次"]
Bind --> Confirm["确认上架"]
Confirm --> UpdateInv["更新库存与库位占用"]
UpdateInv --> End(["完成"])
```

## 性能考虑
- 网络层
  - 使用Retrofit连接池与超时配置，避免频繁建立连接。
  - 鉴权拦截器缓存Token，减少重复认证开销。
- 数据层
  - 批量操作优先（批量插入/更新），减少往返次数。
  - 热点数据缓存（如库位、字典）降低数据库压力。
- 前端交互
  - 列表分页与懒加载，避免一次性加载大量数据。
  - 扫码输入去抖与合并，减少无效请求。
- 并发与一致性
  - 库存扣减采用事务与乐观锁，防止超卖。
  - 长耗时操作异步化，提升用户体验。

## 故障排查指南
- 常见问题
  - 扫码无响应：检查ScanBus订阅与权限配置。
  - 登录失效：检查AuthInterceptor的Token刷新逻辑。
  - 库存不一致：核查事务边界与并发锁策略。
  - 审批卡住：查看审批流状态与审批人权限。
- 定位步骤
  - 前端日志：打印请求URL、参数与响应体。
  - 后端日志：关注异常堆栈与SQL执行时间。
  - 数据核对：对比中间表与最终表的一致性。
  - 复现用例：最小化场景验证问题根因。
